# Дизайн-процесс BookTraveling

Один Git-репозиторий. Холст нужен для обзора и сравнения вариантов. Запускаемый прототип фиксирует согласованное поведение, включая состояния, которые сложно проверить на холсте.

| Где | Что хранится |
|---|---|
| `design/` | Согласованные визуальные правила, ссылки на холст, при необходимости экспорт синтетического макета и записи о передаче в разработку |
| `frontend/prototype/` | Отдельный Vite-вход, синтетические данные, навигация, карта экранов и локальный Agentation |
| `frontend/src/` | Продуктовый интерфейс. Сейчас технический каркас |
| `backend/` | FastAPI, обработка данных и бизнес-правила, в том числе контроль границы чтения |

Прототип открывается на `127.0.0.1:5174`, продуктовый интерфейс через Compose — на `localhost:5173`. Сборки лежат в `frontend/prototype/dist/` и `frontend/dist/` соответственно. Прототип не использует продуктовый API. Общие компоненты стоит выделять после повторного использования согласованного элемента, если это сокращает работу.

## Первый эксперимент

Проверяем один сценарий на вымышленной книге «Маяк на краю бухты»: библиотека → книга → глава → источник. Дополнительный путь: ошибка загрузки → повтор → глава. Граница чтения — глава 1. Карта и ссылки на состояния доступны по `/#/flow`. Используй одну и ту же последовательность и одну и ту же правку при сравнении инструментов.

| Этап | Что сделать | Что считать успехом |
|---|---|---|
| Направление | Выбрать два референса в GradientDeck. С UI/UX Pro Max предложить для обоих компактную систему и показать одинаковый экран главы | Выбрано одно направление, правила доступны в новой сессии через `design/DESIGN.md` |
| Холст | Сначала Penpot, затем OpenPencil. Создать четыре экрана, связать их и показать ветку ошибки. На выбранном слое изменить текст «Показать источник» | Понятна вся схема, есть прямой переход к экрану, агент меняет нужный слой, результат доступен после повторного открытия |
| Кодовый макет | Пройти основной и ошибочный пути. Проверить ширину телефона, фокус и возврат к главе. Открыть ошибку напрямую и проверить повтор | Два сценария воспроизводятся без API, экран источника показывает только разрешённый синтетический фрагмент |
| Обратная связь | В Agentation отметить `chapter.evidence.open` и `chapter.load.retry`. Первую попытку сделать через Copy, вторую с теми же правками на исходной версии через MCP | С первого раза выбраны нужные элементы, изменение видно после перезагрузки, обе ветки проходятся повторно |
| Новая сессия | Дать Codex репозиторий и только ID элемента либо экрана | Агент находит правила, маршрут и файл без пересказа предыдущего чата |
| Передача | После согласования взять один экран с источником, подключить минимальный продуктовый API и повторить сценарий | Поведение соответствует согласованному коммиту, API не отдаёт данные после границы чтения, оба запуска работают независимо |

Записывай версию инструмента, минуты настройки, время от замечания до проверенной правки, количество уточнений и ручных шагов переноса. Для сравнения холстов выдели до 30 минут на каждый после установки. Для инструмента, который не умеет проиграть межэкранный маршрут, отдельно оцени, достаточно ли его как редактора экранов. По итогам оставь один основной холст. React Flow пробуй только если нужно открывать реальные состояния кодового прототипа с карты и список ссылок уже неудобен.

## Цикл изменений и выпуск

1. Укажи экран, состояние и желаемый результат. В коде ссылайся на устойчивый `data-ui-id`. Меняй карту при изменении переходов.
2. Внеси правку в `frontend/prototype/`. Собери макет и пройди путь, включая затронутую ветку ошибки или пустое состояние.
3. Покажи пользователю ссылки на состояния и кратко перечисли изменения. После согласования запиши SHA, сценарий и принятые решения в `design/handoff/<scenario>.md`.
4. Отдельной задачей перенеси принятый экран в `frontend/src/` и подключи контракт API из `backend/`. Прототип остаётся воспроизводимым на фикстурах. Если перенос приходится повторять, сравни стоимость общего компонента и дублирования.
5. Проверь продуктовый сценарий, в том числе недоступные главы и источники на сервере. Обнови `docs/progress.md`. При необходимости укажи Git-тег согласованного прототипа. Локальный запуск продукта описан в README.

В публичный репозиторий и облачные холсты эксперимента помещай только синтетические данные и разрешённые визуальные материалы. Настоящие книги, заметки, ключи и экспорт с такими данными храни отдельно.
