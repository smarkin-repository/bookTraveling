# BookTravaling — инструкции для агентов

## Продукт и границы

- Прочитай `docs/spec.md` и относящийся к задаче раздел `docs/architecture.md`; для задач интерфейса — `docs/ui-spec.md`.
- Личное приложение, локальный Docker Compose; не разворачивать и не публиковать.
- Сначала подготовить и согласовать UI-макет с пользователем; текущая стартовая страница техническая.
- Сохранять факты текста, интерпретации и личные заметки отдельно. У каждого вывода хранить опорные фрагменты или отмечать неопределённость.
- До выбранной границы чтения не раскрывать поздние события ни через API, поиск, граф, карточки, названия и подсказки, ни в контексте LLM. Проверять серверной логикой и тестами; не обещать абсолютную защиту.
- Не перезаписывать личные заметки при повторном анализе. Не принимать валидную схему LLM за подтверждение истинности.
- API-ключи и книги не коммитить, не выводить в логи. Модель может получать только необходимый контекст.

## Работа

- Следуй `docs/plan.md`; обновляй `docs/progress.md` после значимых этапов, фиксируя проверки и блокеры.
- Python: logging вместо print; для новых CLI — Click. Версии зависимостей и релевантную документацию проверяй перед изменениями.
- Предпочитай локальные тесты с подставным LLM; реальные API-вызовы — отдельные интеграционные проверки.
- Используй `rg` и выборочное чтение. Не устанавливай все plugins или Skills из каталога автоматически.
- Запускай проверки, соответствующие изменению; если не удалось — сообщи об этом.
- В начале проекта стек и схема уточняются; не выдавай каркас за реализованные функции.
