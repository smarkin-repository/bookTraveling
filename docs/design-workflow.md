# Дизайн-процесс BookTraveling

Один Git-репозиторий. Холст нужен для обзора и сравнения вариантов. Запускаемый прототип фиксирует согласованное поведение, включая состояния, которые сложно проверить на холсте.

| Где | Что хранится |
|---|---|
| `design/` | Согласованные визуальные правила, ссылки на холст, при необходимости экспорт синтетического макета и записи о передаче в разработку |
| `frontend/prototype/` | Отдельный Vite-вход, синтетические данные, навигация, карта экранов и локальный Agentation |
| `frontend/src/` | Продуктовый интерфейс. Сейчас технический каркас |
| `backend/` | FastAPI, обработка данных и бизнес-правила, в том числе контроль границы чтения |

Прототип открывается на `127.0.0.1:5174`, продуктовый интерфейс через Compose — на `localhost:5173`. Сборки лежат в `frontend/prototype/dist/` и `frontend/dist/` соответственно. Прототип не использует продуктовый API. Общие компоненты стоит выделять после повторного использования согласованного элемента, если это сокращает работу.

## Первый эксперимент

Проверяем один сценарий на вымышленной книге «Маяк на краю бухты»: библиотека → книга → глава → источник. Дополнительный путь: ошибка загрузки → повтор → глава. Граница чтения — глава 1. Карта и ссылки на состояния доступны по `/#/flow`. Используй одну и ту же последовательность и одну и ту же правку при сравнении инструментов.

| Этап | Что сделать | Что считать успехом |
|---|---|---|
| Направление | Выбрать два референса в GradientDeck. С UI/UX Pro Max предложить для обоих компактную систему и показать одинаковый экран главы | Выбрано одно направление, правила доступны в новой сессии через `design/DESIGN.md` |
| Холст | Начать с OpenPencil. Создать четыре экрана и обозначить ветку ошибки. Связи можно показать на карте прототипа. На выбранном слое изменить текст «Показать источник» | Понятна вся схема, есть прямой переход к экрану, агент меняет нужный слой, результат доступен после повторного открытия |
| Кодовый макет | Пройти основной и ошибочный пути. Проверить ширину телефона, фокус и возврат к главе. Открыть ошибку напрямую и проверить повтор | Два сценария воспроизводятся без API, экран источника показывает только разрешённый синтетический фрагмент |
| Обратная связь | В Agentation отметить `chapter.evidence.open` и `chapter.load.retry`. Первую попытку сделать через Copy, вторую с теми же правками на исходной версии через MCP | С первого раза выбраны нужные элементы, изменение видно после перезагрузки, обе ветки проходятся повторно |
| Новая сессия | Дать Codex репозиторий и только ID элемента либо экрана | Агент находит правила, маршрут и файл без пересказа предыдущего чата |
| Передача | После согласования взять один экран с источником, подключить минимальный продуктовый API и повторить сценарий | Поведение соответствует согласованному коммиту, API не отдаёт данные после границы чтения, оба запуска работают независимо |

Записывай версию инструмента, минуты настройки, время от замечания до проверенной правки, количество уточнений и ручных шагов переноса. Для пробы OpenPencil выдели до 30 минут после установки. Для инструмента, который не умеет проиграть межэкранный маршрут, отдельно оцени, достаточно ли его как редактора экранов. По итогам оставь один основной холст. React Flow пробуй только если нужно открывать реальные состояния кодового прототипа с карты и список ссылок уже неудобен.

## Передача работы между этапами

Скопируй [шаблон](../design/handoff/TEMPLATE.md) в `design/handoff/<scenario>.md`. Для одного изменения используй одну запись. Роли обозначают ответственность, а при работе в одиночку их выполняешь ты вместе с Codex.

| Статус | Кто ведёт | Что должно быть готово для следующего этапа |
|---|---|---|
| `canvas` | Дизайнер | OpenPencil: ссылка на файл или экспорт, версия, фрейм или слой. Указаны экран, состояние, визуальная правка и её влияние на поведение. При отсутствии MCP достаточно экспорта или скриншота с этими данными. |
| `prototype` | Разработчик / Codex | Изменение в `frontend/prototype/`, маршрут для просмотра, стабильный ID, синтетические данные. При изменении сценария обновлены маршруты и карта из `flow.ts`. |
| `review` | Проверяющий | Записаны результат сборки, пройденные маршруты и замечания Agentation. Визуальное замечание возвращается в `canvas`, расхождение в поведении — в `prototype`. |
| `approved` | Владелец задачи | Подтверждены объём правки и точный SHA проверенного прототипа. Разрешение на перенос в продукт фиксируется явно. |
| `product` → `done` | Разработчик и проверяющий | Экран перенесён в `frontend/src/`. Если нужен API, он подключён через `backend/`. Проверены согласованный сценарий и граница чтения на сервере там, где она затронута. В записи есть ссылка на реализацию и результат проверки. |

OpenPencil хранит визуальный замысел. React-прототип показывает поведение. Карта читает связи из `flow.ts`; перенос карточки на холсте карты меняет её расположение, а изменение сценария оформляется в коде. Vite даёт адрес для проверки. Если инструмент или проверка недоступны, запиши блокер и следующий шаг в handoff.

Пример команды для Codex:

> `$booktraveling-design` Перейди с холста в прототип для `chapter.evidence.open`. Перенеси «Показать источник» под наблюдение по приложенному фрейму OpenPencil. Сохрани переход на `/#/source`. Проверь маршрут `/#/chapter` и обнови запись передачи.

Другой участник может продолжить по той же записи: «`$booktraveling-design` Возьми `design/handoff/chapter-evidence.md` и проведи ревью». При выходе из этапа оставь статус, подтверждение результата и конкретное действие для следующего ответственного. После значимой вехи обнови `docs/progress.md`.

В публичный репозиторий и облачные холсты эксперимента помещай только синтетические данные и разрешённые визуальные материалы. Настоящие книги, заметки, ключи и экспорт с такими данными храни отдельно.
